# Contributing

Issues and pull requests are welcome.

## Build and test

You need macOS 14 or later and the Swift toolchain (Xcode or the Command Line Tools).

```bash
make test         # unit tests (what CI runs)
make app          # universal, ad-hoc signed build/PRPulse.app
make screenshots  # re-render docs/images with fake data (English UI)
```

With only the Command Line Tools installed, use `make test` or `bash scripts/test.sh` instead of plain `swift test`, which can lose the Swift Testing macro plugin on incremental builds.

To work on the interface without a GitHub account, run the app with fake data: `PRPULSE_DEMO=pending|fresh|empty|error|unconfigured|many`.

## Where things live

```text
Sources/PRPulseCore   rules, notification planner, agents, auth (pure, tested)
  Provider/           what the app needs from a forge: PullRequestProvider, ProviderError, token storage
  GitHub/             the GitHub implementation (GraphQL client, mappers) and its sign-in (GitHub/Auth)
Sources/PRPulse       the macOS shell: status item, popover, wizard, settings
Tests/                unit tests (Swift Testing)
scripts/              build, dmg, icon and test helpers
docs/images/          the README pictures, generated by `make screenshots`
```

A new forge implements `PullRequestProvider` in its own folder under `Sources/PRPulseCore`.

## Before you open a pull request

- Keep the rules in `PRPulseCore` covered by tests, and run `make test`.
- Strings go in both `Resources/en.lproj` and `Resources/pt.lproj`; a test fails when one is missing or unused.
- Add a line under **Unreleased** in `CHANGELOG.md` for anything a person using the app can notice.
- For a visual change, attach a before and after picture.
- Code and comments are in English. Prefer small methods and few comments.

Releases are cut by the maintainer, because updates are signed with a key that stays on their Mac.
